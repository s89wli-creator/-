## 1. ما تم بناؤه

| البند | التفاصيل |
|---|---|
| **إعدادات المبيعات** | المسارات (Tracks) بخط مبيعات مستقل لكل مسار، محرر مراحل (إعادة تسمية، ترتيب، إضافة، حذف آمن)، أسباب الفوز/الخسارة/التأجيل/عدم الملاءمة، حقول إضافية (نص، رقم، تاريخ، قائمة، نعم/لا) لكل كيان ولكل مسار |
| **العملاء** | إضافة وتعديل وحذف ناعم، بحث عربي ذكي (أ/إ/ا، ة/ه، التشكيل، الأرقام الهندية)، فلاتر (المسار، المندوب، الحالة، المدينة)، ترقيم صفحات، ملف عميل بسبعة تبويبات |
| **كشف التكرار** | السجل التجاري ← الرقم الضريبي ← الموقع ← الهاتف ← الاسم المطبّع + المدينة (تشابه ≥ 85%). "شركة النقل السريع المحدودة" = "مؤسسة النقل السريع" في نفس المدينة. خيار "إنشاء رغم ذلك" مسجّل في التدقيق |
| **جهات الاتصال** | الجوال والبريد **مشفّران** (AES-256-GCM بمفتاح مستقل لكل شركة) مع بصمة للبحث دون فك التشفير؛ "عدم التواصل" بالسبب والوقت؛ الحذف يمحو البيانات الشخصية فعلياً؛ البيانات الشخصية لا تُنسخ إلى سجل التدقيق |
| **الاستيراد من Excel/CSV** | قراءة حسب المحتوى لا الامتداد، ربط تلقائي للأعمدة بالعربي والإنجليزي، **إقرار إلزامي بمشروعية استخدام البيانات**، تحقق لكل صف (أخطاء مانعة وتنبيهات)، كشف التكرار مع قاعدة البيانات وداخل الملف، قرار لكل صف (إنشاء/دمج/تخطٍ) والافتراضي الآمن للمكررات "تخطٍ"، الدمج يملأ الحقول الفارغة فقط ولا يستبدل، تنفيذ ذري (الكل أو لا شيء)، الإلغاء يحذف البيانات الخام |
| **التصدير** | Excel وCSV حسب الفلاتر، محمي من حقن الصيغ (Formula Injection)، يدعم العربية، مسجّل في التدقيق |
| **الفرص وخط المبيعات** | لوحة Kanban بالسحب والإفلات + زر "نقل إلى" للجوال، سجل كامل للمراحل، الإغلاق (فوز/خسارة/تأجيل) **يتطلب سبباً من النوع الصحيح**، الفوز يحوّل العميل إلى "عميل فعلي" |
| **الزيارات** | جدولة وتغيير موعد وإلغاء، تسجيل الوصول مع الموقع (اختياري، ليس دليلاً وحيداً)، **نموذج نتيجة في شاشة واحدة** (النتيجة، الاهتمام، الخطوة التالية، موعد المتابعة بنقرة، ملاحظات)، إنشاء مهمة متابعة تلقائياً |
| **التحريك بالأحداث (بلا تخمين)** | جدولة زيارة ← "زيارة مجدولة"، إتمامها ← "تمت الزيارة". التحريك للأمام فقط عبر المراحل المفتوحة، لا يغلق ولا يعيد فتح صفقة، والزيارة نفسها هي الدليل المسجّل |
| **المهام** | مهامي/اليوم/المتأخرة/القادمة/الفريق/المنجزة، الأنواع والأولوية، المهام التلقائية مميزة |
| **الملاحظات وسجل النشاط** | سجل موحّد لكل عميل (append-only) |
| **لوحة القياس** | قيمة الخط، الرابحة والخاسرة، نسبة الفوز، العروض، الزيارات ونسبة إنجازها، المتابعات في موعدها، المهام المتأخرة، الفرص حسب المرحلة، أسباب الخسارة، أداء كل عضو، فلترة بالفترة والمسار. التعريفات من `docs/01-PRD.md` §9 |
| **صلاحيات المندوب** | يرى ويعدل عملاءه المسندين فقط (أو يقرأ الكل دون تعديل إن فعّلت الشركة ذلك)، لا يعيد الإسناد، لا يحذف، لا يستورد ولا يصدّر، ولا يرى لوحة القياس |

**الواجهات الجديدة (9):** لوحة القياس، العملاء، ملف العميل، الاستيراد، خط المبيعات، الزيارات، تفاصيل الزيارة، المهام، إعدادات المبيعات. والرئيسية تعرض للمندوب زيارات اليوم ومهامه.

## 2. الاختبارات

| المجموعة | العدد |
|---|---|
| `packages/shared` (التطبيع العربي، الهواتف، المعرّفات، الصلاحيات) | 25 |
| `packages/db` (RLS يشمل الجداول الـ15 الجديدة تلقائياً) | 8 |
| `apps/api` | 120 |
| — منها عزل الشركات (مجسّ لكل مسار من الـ47 الجديدة + السابقة) | 63 |
| `apps/web` (الترجمة + **فحص آلي أن كل رمز خطأ في الـAPI مترجم**) | 9 |
| **الإجمالي** | **162** |
| عزل الشركات مع تعطيل RLS (طبقة التطبيق وحدها) | 63/63 |
| E2E المتصفح: الأساس | ناجح |
| E2E المتصفح: دورة البيع كاملة (مدير على سطح المكتب + مندوب على جوال 360px) | ناجح، بلا أخطاء Console، وبلا تمرير أفقي في 11 شاشة على الجوال |

### ما كشفته الاختبارات وتم إصلاحه قبل التسليم
- لوحة القياس كانت تعرض "الفرص حسب المرحلة" بأصفار عند وجود مسارات، وتحسب الزيارات المنجزة بتعريفين مختلفين ← وُحّد التعريف وأُضيف اختبار.
- قائمة المندوبين كانت لا تُظهر عضواً انضم قبل دقائق (تخزين مؤقت) ← تُحدَّث الآن عند كل فتح.
- لوحة Kanban كانت تفتح على خط فارغ عند وجود مسارات ← تفتح الآن على الخط الذي فيه صفقات.
- رمز خطأ (الخدمة غير متاحة) بلا ترجمة ← اكتشفه الفحص الآلي الجديد.

## 3. قرارات هندسية

| القرار | السبب |
|---|---|
| تشفير جهات الاتصال على مستوى التطبيق بمفتاح مشتق لكل شركة (HKDF) | بيانات شخصية؛ تسريب قاعدة البيانات وحده لا يكشفها، ونص شركة لا يُفك بمفتاح أخرى |
| الاستيراد متزامن (حتى 5000 صف) داخل معاملة واحدة | أبسط وأضمن (ذري)؛ النقل إلى Worker عند الحاجة لملفات أكبر |
| استخدام `exceljs` وليس حزمة `xlsx` من npm | إصدارات `xlsx` على npm فيها ثغرات معروفة غير مصححة |
| الحذف ناعم للعملاء والفرص | قابل للاسترجاع ويحفظ السجل؛ جهات الاتصال تُمحى بياناتها الشخصية فعلياً عند الحذف |
| قواعد الصلاحيات على مستوى السجل في الخادم (والواجهة تخفي ما لا يُسمح به فقط) | الخادم هو الضامن، والواجهة لا تُظهر أزراراً ستفشل |
